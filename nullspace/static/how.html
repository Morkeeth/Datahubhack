Three agents asked for the same table. None of them could know that.

Every step below happened on 10 August 2026, on a running DataHub. The numbers, the names, the pull request and the rows are read from that instance. Nothing here is an illustration of what could happen.

01 · The miss

A search that returns nothing leaves no trace.

Three agents, in three separate contexts, searched the catalog for revenue by segment. Each found nothing and stopped. Today that is where it ends: no ticket, no record, and no way for any of them to learn that the other two wanted it too.

02 · The record

Nullspace keeps the miss instead.

Each miss creates or increments a ghost — a real DataHub dataset URN tagged ghost, holding the phrase that was wanted and an edge back to every agent that asked. The three searches converge because they resolve to the same URN, so the third agent is the first evidence that this is not one person's problem.

03 · The claim

A builder agent reads the demand and writes the model.

At the threshold a builder agent claims the ghost. It reads the queries the three requesters actually meant to run, infers the grain from them, checks the warehouse for columns that can satisfy it, and writes dbt. It refuses any ghost whose fields no warehouse column can serve, and says which field is missing.

select "segment", "month", sum("mrr") as mrr, sum("churned_mrr") as churned_mrr from {{ source('warehouse_source', 'revenue_events') }} group by segment, month
grain = {segment, month} · measures summed from revenue_events · opened as nullspace-dbt #17
04 · The fill

On merge, the hollow mark becomes a table.

Each mark below is one ghost in the catalog. Hollow means nobody has built it. When the pull request merges, dbt runs and the model materialises — and only then does the record change state. If dbt fails, the write is refused and the mark stays hollow. Solid is a thing that was read back, not a label that was applied.
