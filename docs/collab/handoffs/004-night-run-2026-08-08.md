## 1. The pitch (playbook #16 — written before more code)

> **Nullspace is demand-side metadata: a catalog entry for data that does not exist yet.**
> Agents search a catalog, miss, and fail silently in three separate contexts. Nullspace
> turns each miss into demand on a shared namespace. When enough independent agents ask
> for the same thing, a builder agent claims it, writes the model, opens a PR — and the
> ghost goes solid, carrying the names of the agents that asked for it.

**Glossary — pick one word and keep it (playbook #19).** Use these exact terms everywhere:

| Term | Means | Never say |
|---|---|---|
| **ghost** | a demanded asset that does not exist yet | placeholder, stub, virtual dataset |
| **demand** | count of *distinct* agents that asked | votes, requests, hits |
| **claim** | a builder agent taking ownership of a ghost | assign, lock |
| **solid / solidify** | the ghost became a real asset | materialize, publish |
| **requester** | an agent whose miss created demand | user, consumer, client |

## 4. 🌙 THE MOONSHOT — the ghost has a contract

Right now a ghost is a tombstone: "this doesn't exist." The moonshot makes it a
**promise**.

When an agent's search misses, Nullspace returns a **proposed schema contract** for the
asset — the fields it would have. The agent can **register a query against the ghost
now**. When the ghost goes solid, Nullspace validates every queued query against the real
schema and tells each requester: *your query runs now.*

**An agent writes SQL against a table that does not exist, and gets told when it becomes
real.** That is pre-ordering data, and no catalog on earth does it.

Small in code: contract = field list on the ghost; queued query = string + the validation
already needed for schema. **Lane B owns it.** It is the last thing built and the first
thing cut if Phase 1 slips — but if it lands, it is the demo.

## 5b. ADDENDUM for Lane A — a hardcoded schema, and the one-line fix

`nullspace/builder.py::build_and_solidify` passes
`schema_fields=["cohort_id", "trials", "conversions", "trial_to_paid_rate"]`
for **every ghost, regardless of what was demanded**. A ghost for "monthly
recurring revenue by segment" would be solidified with trial-to-paid columns.
This is exactly what playbook #32 says judges grep for.

**Lane B has already built the honest source.** When you implement **L1 (schema)**,
take the fields from the contract store rather than the literal:

```python
from nullspace.agents.contracts import ContractStore
fields = ContractStore().demanded_schema(want)   # union of what agents asked for
```

Verified live: three agents registering real queries produce
`['segment', 'mrr', 'month', 'churned_mrr']`. Fall back to the literal only when
no queries were registered, and say so in the output rather than silently.

The moment `schemaMetadata` is published, `contract_status` flips from
`0 running / 3 blocked` to `3 running` on its own — that is the demo's payoff
shot, and it is currently gated on L1 alone.
